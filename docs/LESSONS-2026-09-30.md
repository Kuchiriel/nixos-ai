## 1. Verifier quebrado é o padrão, não a exceção (3ª vez)
O `expected` do T3-synthesis era **378** (escrito à mão, assumindo
k6/k7 em `a.csv` que só tem k1..k5). Os modelos responderam **123** —
a resposta **certa** — e eu marquei como falha por horas.
Anteriores: fixture do bytecopy (`printf` sem `%s`), verifier do
Harbor (câmera do src).
**Regra:** expected numérico **derivado do fixture por código**.
Verificação cruzada: `python3 -c` recalcula e compara com o que o
modelo respondeu, antes de culpar o modelo.

## 2. Budget de token é derivado, NUNCA chutado
`_ctx_derived_max_tokens(ctx)` = `ctx//12` com piso existe desde
19/09. O nightwatch usava 1024 hardcoded → grammar truncava o JSON
(`Unterminated string at char 2159`, sempre no mesmo ponto). Meu
"fix" de 4096 hardcoded era o mesmo buraco. Corrigido: helper em
`core/context_budget.py` (neutro), agent re-exporta, nightwatch herda.
Grammar-limited response_format garante JSON **válido**, não
**ilimitado**.

## 3. Fronteira do supervisor é lei
Tentar `from jarvis.core.agent import _ctx_derived_max_tokens` no
nightwatch **viola** `test_supervisor_does_not_own_the_loop`. O
nightwatch não importa o loop — pra isso existe `runtime.run`.
Helper neutro em `context_budget.py`, não em `agent.py`.

## 4. Grammar conserta FORMA, não CONTEÚDO
`response_format` json_schema garante que o JSON parseia. Não
garante que o `old_text` do modelo case com o arquivo real. As duas
metades do patcher podem falhar independentemente:
- forma (JSON truncado) → corrigido pelo budget (#2)
- conteúdo (`old_text` não bate) → **ainda quebrado, é a falha 2**
Grammar não substitui `apply_hunk`/`ast.parse` na verificação.

## 5. `python -c` está na allowlist-negativa
O `safe_editor` valida antes de escrever (`ast.parse`) — por isso o
`leading zeros` do fallback foi barrado em vez de corromper o
arquivo. Mas `python3 -c` inline é **recusado** (`-x` bloqueado);
só `python3 <arquivo>` no jail passa. A lição que o nightwatch
aprendeu ("use `python -c 'compile()'`") é **boa mas aponta pra um
caminho que o próprio harness bloqueia**. Ao ler lição do nightwatch,
verificar se o caminho sugerido é executável.

## 6. Nightwatch é o canário do harness real
Ele roda o **mesmo loop de patch+validação+commit** que o REPL, sem
o humano no meio. Quando falha, é falha de harness reproduzível
(gramática truncada, budget, boundary) — não de modelo. Rodar ele é
barato e acha bugs que a gente não acha interagindo. Valor real dele
**não é os commits que ele faz** (zero até agora) mas **ser o
motor principal de teste** (ele roda enquanto a gente dorme).

## 7. Auto-corrigir é pré-condicionado por aplicar-patch
Hoje o nightwatch só **grava lições** no AGENTS.md. Ele não consegue
aplicar um `old_text`, então nunca vê se acertou — tentativa-e-erro
sem feedback é ciclo cego. **Se a falha 2 (`old_text` não casa) for
resolvida**, ele passa a poder se auto-corrigir de verdade (teste
roda → feedback real → lição vira aprendizado). É a pré-condição do
`RHO`/retro-harness (arXiv 2606.06324): harness que melhora com as
próprias trajetórias.

## 8. n=1 é diagnóstico, n≥3 é medida (revisão do dia)
mission-kit com n=1 deu 0/4; com n=3 deu 5/12. O n=1 media
**variância**, não capacidade. Mesma armadilha do A/B de idioma.
Piso honesto: **n≥3** pra qualquer task binária antes de tirar
conclusão de modelo.
