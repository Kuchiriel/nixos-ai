## CATÁLOGO DA FRUSTRAÇÃO (o que o usuário sente, com causa)

1. **Desiste após 1 erro** (4 runs): sem persistência nem 2ª estratégia.
   Causa: modelo (falta) + harness (sem recovery coach — CORRIGIDO, com
   1 recovery verificada).
2. **Agente cego** (T1-agent ×2): Agent default só tem read_file de path
   exato — tarefa sem path é impossível P/ QUALQUER modelo. 100% harness.
3. **Fast tier anulado** (T1-qwen-repl): param-count jogou Qwen3-4B em
   "tiny" sem tools. 100% harness — CORRIGIDO (registry vence regex).
4. **rc=0 na rendição** (quase todos): harness declarava sucesso. 100%
   harness — CORRIGIDO (stuck/loop_abort honestos + loop detector).
5. **Loop sem progresso** (README×2, search×3): REPL sem loop detector
   (Agent tinha). 100% harness — CORRIGIDO (portado).
6. **Especulação sem evidência** (T3 ×2): responde de priors, lê nada,
   confiante. Modelo (+harness: sem regra evidence-before-answer —
   adicionada à disciplina, não verificada em rerun).
7. **Age-errado rápido vs trava silenciosa**: Bonsai age (errado),
   Qwen trava/loops. Estilos de falha distintos, mesmo placar. Modelo.

## QUANTO É MODELO vs HARNESS (veredito)

- Harness respondia por ~metade do abismo OBSERVADO: itens 2–5 acima são
  100% harness, todos corrigidos nesta sessão com teste. O item 1 é
  misto (coach verificado 1×, mas 1 hint não cria persistência).
- Modelo responde pelo resto: nenhum run mostrou plano multi-passo
  espontâneo, exploração sistemática ou auto-verificação (rodar testes
  após editar — está no template RULES e ninguém obedeceu). Bonsai no
  Opencode frustrando é CONSISTENTE com isso: harness bom não injeta
  persistência/juízo que o modelo não tem. Q2_0 ternário comprime
  exatamente essas capacidades (planejamento, nuance), não as mecânicas.
- Paridade com flash models em AUTONOMIA: NÃO, com 4–8B locais (teto
  físico, não preguiça). Paridade em TRABALHO SUPERVISIONADO MECÂNICO:
  SIM, com o harness corrigido (35/35) — é o regime honesto do fast tier.

## O QUE MUDA NO USO (recomendação prática)

- Fast tier = pair-programmer supervisionado (prompts com path, 1 passo
  por vez); strong (MoE) = tentativas profundas; cloud flash = autonomia.
- Router já suporta: model_requirements por tarefa + escalada manual.
  Próximo passo técnico (NÃO implementado — propor): escalada automática
  Agent→strong em stuck (sinal `session.stuck` já emitido).
- Custo real da iteração local: cada run UX custou 5–40 min (CPU) —
  velocidade de iteração TAMBÉM é UX; GPU serving mitiga tempo, não juízo.
