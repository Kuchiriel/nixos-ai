events (`task_started`, `task_completed`, `task_failed`, `loop_detected`) e as
rotas CLI `jarvis control status/state` já leem `StateStore`. Agora é conectar a
fonte real de eventos: o `Harness` do Nightwatch já emite `self._emit("task_*")`
pelo EventBus global; a integração consome e popula `Sections.AGENT`. Restam:

1. Verificar se o `Harness` usa a instância global do EventBus (ou cria outro).
2. Verificar se `StateStore` persiste e sobrevive a restart.
3. Verificar se o CLI `jarvis ask` / `jarvis control` / `jarvis nightwatch` pode
   rodar com backend Bonsai (port 8080 já ativo) e se `JARVIS_LLM_BACKEND` chega
   até o `LLMClient`.
4. Executar um teste real de tarefa no harness com LLM real (não mock), projetos
   de `~/projects`, ao menos "mindless" (ex: renomear um arquivo, adicionar um
   docstring, versionar um script existente) para validar o pipeline de ponta a
   ponta com evidência observável no StateStore e no Event Timeline do WebUI.
5. Atualizar BUFFY.md do monorepo e HANDOFF.md do nixos-ai com o que foi
   verificado (nível de evidência real, não claim).

Bloqueios conhecidos:
- Se o harness não injetar persona/LLM no EventBus de forma que o Control Plane
  consiga observar, isso deve ser documentado e corrigido antes do teste real.

  declarar PASS.
